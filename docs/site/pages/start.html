Start — From Zero to SSH

Six steps from clone to shell. Works on Linux, macOS (OrbStack/Docker Desktop), Windows + WSL2. GHCR prebuilts mean no 10-minute first build.

1. Clone

Grab the IaC repo — all definitions are in docker-compose.yml + Dockerfiles + *.sh.

git clone https://github.com/1999AZZAR/ghost-machines.git
cd ghost-machines

2. Host Setup (Linux only — once)

Installs LXCFS so htop/free inside the container reports cgroup limits, not host totals.

Auto-detects your package manager (apt/pacman/dnf/zypper/apk).

Skip on macOS/WSL — start.sh auto-skips LXCFS via --no-lxcfs.

make setup-host # or ./setup-host.sh
# checks Docker, installs LXCFS if on Linux, prepares systemd unit

3. Choose an image source

A. Prebuilt (GHCR) — recommended, ~1 minute

One package per engine, multi-arch (amd64 + arm64). start.sh pulls it automatically if missing.

./start.sh --prebuilt ubuntu -m single
# explicit ref / refresh / pin
./start.sh --image ghcr.io/1999azzar/ghost-machine-debian:v2.1.0 -m single
./start.sh --prebuilt debian -m single --pull
B. Local build — 5–15 min, first time only

Compiles the Dockerfile in the repo and tags <engine>-template:latest.

./start.sh -e ubuntu -m single --build
make build-debian # build only, start later without --build

Mixed up? start.sh always prints the resolved image:

[IMAGE] ghcr.io/1999azzar/ghost-machine-ubuntu:latest (GHCR prebuilt, no local build)
[IMAGE] ubuntu-template:latest (local build from Dockerfile)

Rule: a reference containing / is pulled, a plain tag is built. --build is ignored for registry refs.

4. Launch

Interactive (asks engine + mode):
./start.sh
Non-interactive:
./start.sh --prebuilt ubuntu -m single
./start.sh -e debian -m dual --build
./start.sh -e arch -m power -p 3333
Modes:
-m single # 1c / 8G — standard
-m dual # 2 × 1c / 8G — ports 2223 + 2224
-m power # 1 × 2c / 16G — heavy builds
-m half # 50% host CPUs/RAM

5. Connect + Work

# single / power / half mode (container: ghost-machine-single|power|half)
ssh -p 2223 developer@localhost
# dual mode, second machine (container: ghost-machine2)
ssh -p 2224 developer@localhost
# pass: ghost (sudo: ghost) root: ssh -p 2223 root@localhost
# or, if ~/.ssh/id_ed25519.pub exists on host — auto-mounted, no password
# no SSH at all: docker exec -it ghost-machine-single bash

Your home is mounts/ubuntu1 (or mounts/tenants/<id> in WaaS). Delete the container — work stays on host.

Ports: only 22 is published. To reach a dev server inside the sandbox:

ssh -p 2223 -L 3000:localhost:3000 developer@localhost # then http://localhost:3000

Editor: VS Code Remote-SSH / JetBrains Gateway / Zed → ssh -p 2223 developer@localhost.

Not sure of the port?

./start.sh status
# SSH endpoints:
# ghost-machine-single ssh -p 2223 developer@localhost

Host key changed after a rebuild?

ssh-keygen -R "[localhost]:2223" # or use ghost-ssh from aliases.sh

6. Stop / restart / remove

./start.sh status # state, image, SSH port
./start.sh logs # follow entrypoint/sshd output
./start.sh restart # restart in place
./start.sh stop # remove containers + network — mounts/, images, .env stay
docker compose --profile dual stop # pause instead (container kept)
docker compose --profile dual start # resume
./clean.sh -a -y # also delete images
./clean.sh --nuke --hard -y # images AND mounts/ (destructive)

stop never touches your work: the home directory is a bind mount on the host. Only --hard wipes it.

Customization

./start.sh -e ubuntu -m single -p 2225 # custom SSH port (useful when 2223 taken)
./start.sh -e debian -m single -t $TUNNEL_TOKEN # Cloudflare Tunnel — no port-forward needed
./start.sh --no-lxcfs # skip LXCFS (macOS/WSL default)
SSH_PASSWORD_AUTH=false ./start.sh # key-only, disable password (via .env)
./start.sh dual --update-harness # refresh opencode/agy/rtk to latest

Troubleshooting

  • Port 2223 in use — pass -p 2225 (dual then uses 2225+2226) or ./start.sh stop first.
  • Connection refused — ./start.sh status, then ./start.sh logs: the entrypoint may still be running.
  • Permission denied (publickey) — SSH_PASSWORD_AUTH=false with no authorized key; set it back to true and recreate.
  • Host key verification failed — new container, new key: ssh-keygen -R "[localhost]:2223".
  • Permission denied on mounts/ — re-run ./start.sh (re-syncs UID/GID from id -u/g).
  • It rebuilt when I wanted the prebuilt image — no local tag existed; use --prebuilt.
  • --build does nothing — the reference is a registry image; drop GHOST_IMAGE or use the local tag.
  • htop shows host RAM — install LXCFS: make setup-host on Linux.
  • GHCR pull denied — echo $GH_TOKEN | docker login ghcr.io -u USERNAME --password-stdin.
