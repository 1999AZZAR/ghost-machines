Core Concept

Each container is a curated specimen. Narrative and technical metadata are separated for clarity. All workspaces hydrate from host bind mounts on boot, ensuring continuity across reloads.

Immutable core (images) + mutable state (mounts/) = throw-away without loss. make start provisions; clean.sh prunes.

User Management & Authentication

Tenant-based: each host can vend many isolated users. Each tenant is a specimen with its own SSH port, CPU/RAM quotas, and storage mounts/tenants/<id>.

Roles

HOST — Full access. Can create/delete tenants, run tenant.sh, manage GHCR pulls, clean --nuke.
TENANT (developer) — Can SSH on assigned port, sudo with ghost, work in own mount. Cannot see other tenants.

Registration Flow

  1. Host: ./tenant.sh add alice --engine debian --port 2225 — auto-creates mount and SSH.
  2. Tenant: ssh -p 2225 developer@localhost — password ghost or pre-injected ~/.ssh/id_ed25519.pub.
  3. Verify: ./tenant.sh list shows RUNNING + port + size.

Inviting / Removing

Host invites via tenant.sh add; removal via tenant.sh delete alice -y (optionally --archive). No per-tenant 5-user limit — each container is single-user.

Multi-Tenant Aggregation Hub

The host aggregates multiple engines on one machine, pooling CPU/RAM into a unified ghost_sandbox network. Each tenant is isolated via non-overlapping mounts and per-tenant cgroup limits — no noisy neighbor.

Cross-engine logic: One host can run Ubuntu for Rust, Alpine for Go, Debian for Node — all on different ports, sharing host kernel but not files.

Snapshot Retention

All mounts are mirrored via snapshot.sh into snapshots/ with SHA-256 + .meta.json. By default, caches (node_modules/.cache, target/, __pycache__) are excluded to keep archives lean. Restore verifies SHA and keeps atomic backup.

./snapshot.sh -o backup.tar.gz
./restore.sh backup.tar.gz --force

Engine Specimens

UBUNTU (STANDARD) — ubuntu:latest · apt-get · PPA — Default for agents, richest toolchain.
DEBIAN (SLIM) — debian:stable-slim · apt-get — Stable, smallest apt base.
ALPINE (MUSL) — alpine:latest · apk — Ultra-light, musl libc.
ARCH (ROLLING) — archlinux:latest · pacman — Latest upstream.

Each specimen ships: Go 1.24, Rust rustup, Node 22 + Bun, uv/pipx, Helix/Micro/Lazygit, agy/opencode/kilo + rtk, 7 HeLa MCP.

Layout Customization

Persistent ordering: tenant mounts under mounts/tenants/<id> survive reboots and container recreation — layout is host-file, not ephemeral. Rearranging is simply moving tenants or re-adding with different --port/--cpu/--mem.

Auto-Provisioning

Zero-touch: no need to pre-pull. ./start.sh -e ubuntu -m single auto-builds if no GHCR image found; ./tenant.sh add alice --engine debian auto-allocates port from 2225 if omitted. LXCFS auto-detects via /var/lib/lxcfs/proc.

./start.sh -e alpine -m power # 2c/16G
./tenant.sh add carol --engine alpine --port 2227 # explicit

Logic Matrix

Local automation matrix linking engines, modes, and cleanup:

  1. LISTEN & MATCH — Match engine + mode + GHOST_IMAGE to compose profile (dual/single/power/half).
  2. EVALUATE — Resolve UID/GID, LXCFS, SSH key, tunnel token.
  3. IF/ELSE IF — If GHCR image exists → reuse; else → build via Buildx.
  4. WEBHOOK DISPATCH — Cloudflare Tunnel if TUNNEL_TOKEN set.
  5. INTER-WIRING — Tenant snapshots chain to restore (max 5 deep).
  6. MANUAL OVERRIDE — ./clean.sh --nuke for full purge test.

How-To Guide

Placing a Workspace (Single)

  1. git clone https://github.com/1999AZZAR/ghost-machines.git && cd ghost-machines
  2. make setup-host (once, Linux)
  3. docker pull ghcr.io/1999azzar/ghost-machine-ubuntu:latest
  4. GHOST_IMAGE=ghcr.io/1999azzar/ghost-machine-ubuntu:latest ./start.sh -e ubuntu -m single
  5. ssh -p 2223 developer@localhost

Multi-tenant

  1. ./tenant.sh add alice --engine debian --port 2225
  2. ./tenant.sh list · stats
  3. ./tenant.sh delete alice -y

Security Protocol

Multi-layered: dev defaults developer:ghost / root:ghost (rotate via docs/security-todo.md P0), key-only via SSH_PASSWORD_AUTH=false, per-tenant authorized_keys injection, UID/GID sync via entrypoint.sh, GHCR pull auth via GITHUB_TOKEN.
